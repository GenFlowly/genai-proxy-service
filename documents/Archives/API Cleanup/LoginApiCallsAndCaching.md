## Cross-cutting observations (updated 2026-10-30 after the cleanup pass)

- ~~Only `/providers` ever skips a network call~~ **FIXED 2026-10-31** — `/providers`, `/request-agents` and `/agents` all skip network now (session cache / version gating via react-query); `/models` is one shared paint-then-refetch query; the history trio stays paint-then-always-refetch on the consolidated `customerListCache` modules (its `projects` counter is already returned by /onboard for a future migration); the conversation load has no caching at all (by decision below).
- ~~Heaviest waste: the duplicate `/agents` call~~ **FIXED** — the agents fan-out now runs once; `AgentPickerWidget` shares `customerAgentsCache`.
- ~~Per-conversation Message-table Queries for vendors~~ **FIXED** — vendors are denormalized onto the Conversation row; old rows heal on first listing.
- **`CustomerVendorApiKeys` is still hit with different access patterns**: one Query returning all rows (`/onboard`) vs per-vendor point GetItems (`/models`, and `/embedding-models` when Settings opens) — inherent to `/models` needing decrypted keys.
- **`CustomerProfile` is read on every single request** — still true; fewer requests per login now (`/embedding-models` and the duplicate `/agents` left the login burst), but each remaining call pays the auth GetItem.
- ~~Prefetch bundle fires for not-yet-onboarded customers~~ **FIXED 2026-10-31** — `useRequestAgents`/`useCustomerAgents` wait for the /onboard sync to settle before their first fetch (also kills the onboard-vs-prefetch race for first-time logins); only `/providers` still fires on session auth, which is correct (platform-static, needed by the setup wizard itself).
- **Backend caches invisible to the frontend**: `/providers`' process-lifetime Kotlin `providerCatalogCache` and `/embedding-models`' per-(customerId, vendor) probe-cache table.
- **Login burst after this pass**: `/onboard` + `/providers` + `/request-agents` + `/agents` (once) + `/models` (once) + `/conversations` + `/conversations/pinned` + `/projects` = 8 calls, down from 11, with the Message-table read amplification gone entirely.

## Decisions

- **Conversation content (#11) stays uncached — decided 2026-10-30.** Three reasons: localStorage is ~5MB/origin with a synchronous API and full histories (message text, tool results, web sources, thinking steps) would blow the shared quota; the response carries in-flight durable-run placeholders used to reattach to live streams after reload, which must never be served stale; and it would persist full conversation content at rest on the machine. Benefit is also minimal — it only fires on deep links/refreshes.
